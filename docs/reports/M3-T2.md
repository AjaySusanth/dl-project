## 3. What I implemented

`lag_baseline` returns two arrays:

- `b1`: lag 24 hours, same hour yesterday.
- `b2`: lag 168 hours, same hour last week.

For every forecast origin, target, and zone, the function looks up:

```text
source_hour = origin_ts + h - lag
```

where `h` ranges from one through the configured horizon. It validates input
schemas, duplicate zone-hour keys, timestamps, non-negative pickups, and
missing historical source hours.

## 4. Learning explanation

These baselines assume demand has a repeating daily or weekly pattern. They
are intentionally simple: tomorrow's 10:00 demand is estimated from today's
10:00 demand, and next week's 10:00 demand is estimated from this week's
10:00 demand. They do not learn parameters, so they are useful controls for
whether the deep models add predictive value.

Because the horizon is six hours and the smallest lag is 24 hours, every
source observation is strictly before the forecast origin. This prevents the
baseline from accidentally reading future information.
