## 3. What I implemented

Added `select_zones`, which derives the training timeline from the hourly table
and applies the first configured split fraction. It calculates each zone’s
training-period total pickups and nonzero-hour fraction, removes ineligible
zones, ranks the remainder, divides it into three ordered tiers, and chooses
evenly spaced IDs from each tier.

The output preserves every timestamp for the selected zones and the
architecture-defined hourly columns.

### File-by-file explanation

#### `src/data/zones.py`

- **Responsibility:** Select representative modeling zones.
- **Changes:** Added validation, train-period statistics, eligibility filtering,
  deterministic tier selection, logging, and output shaping.
- **How it works:** `np.array_split` forms three ordered volume tiers and
  `np.linspace` chooses evenly spaced IDs within each requested tier.
- **Why this design:** It avoids selecting only adjacent or nearly identical
  volume values within a tier while remaining deterministic.
- **Connections:** M2-T5 will call it and write the returned table as
  `hourly_selected.parquet`; later feature code consumes that table.

## 4. Architecture and data flow

`hourly_all.parquet + config + zone lookup → select_zones → selected hourly table`

Only the training period influences eligibility, ranking, and tier placement.
All timestamps for selected zones remain in the returned table for later
chronological splitting.

## 5. Key technical decisions

| Decision | Reason | Alternative considered | Trade-off / consequence |
|---|---|---|---|
| Use the first split fraction to define training hours | Matches the documented chronological 70% training period | Use all data; rejected because it leaks future demand into selection |
| Filter before tiering | Prevents mostly empty zones from occupying selected slots | Tier first then filter; not considered | Eligible tier sizes can become too small and fail explicitly |
| Select evenly spaced IDs within each ordered tier | Matches “spread evenly” and is deterministic | Always take the tier extremes; not considered | Selection may include less-volume zones within a tier |
| Return all timestamps for selected zones | Downstream splits need complete histories | Return training rows only; rejected | Output contains future rows, but they were not used for selection |

## 6. Deep learning / data-science explanation

- **Concepts used:** Representative sampling and leakage prevention.
- **Inputs and targets:** The input is hourly pickup demand; selection uses
  training-period total pickups and nonzero-hour frequency.
- **Math or loss function:** Nonzero fraction is
  `hours with pickups > 0 / training hours`.
- **Training/evaluation implications:** Selecting zones with future-period
  demand would allow test information to influence the model population.
- **Leakage and reproducibility safeguards:** Only chronological training hours
  affect filtering, ranking, and tier assignment; IDs are selected
  deterministically.
