### File-by-file explanation

#### `tests/test_ingest.py`

- **Responsibility:** Protect the M1 ingestion behavior.
- **Changes:** Added reusable fixtures and five deterministic tests.
- **How it works:** Synthetic DataFrames isolate each rule; a subprocess
  invokes the CLI so its real exit status and stderr are tested.
- **Why this design:** Small fixtures make failures easy to understand and
  avoid depending on downloaded data for unit-test correctness.
- **Connections:** Tests call `src.data.ingest` and `scripts/ingest.py`.

## 4. Architecture and data flow

The test coverage follows:

`synthetic raw trips → clean_trips → aggregate_hourly → asserted hourly contract`

The CLI test covers the failure branch:

`missing configured files → warning + nonzero CLI status`

## 5. Key technical decisions

| Decision | Reason | Alternative considered | Trade-off / consequence |
|---|---|---|---|
| Use synthetic fixtures | Required for deterministic edge cases | Test only downloaded data; rejected | Tests do not measure real-data distributions |
| Assert exact cleaning counts | Verifies each rule rather than only final row count | Assert only output length; rejected | A misclassified rule is detected |
| Invoke the CLI in a subprocess | Proves actual command exit behavior | Call `main()` directly; not considered | Slightly more overhead, but tests the script boundary |

## 6. Deep learning / data-science explanation

- **Concepts used:** Data-contract testing and time-series completeness.
- **Inputs and targets:** Tests verify that trip rows become valid zone-hour
  pickup targets.
- **Math or loss function:** Duration tests verify the aggregation input used
  later for fleet busy-time calculations.
- **Training/evaluation implications:** Incorrect zero filling or timestamp
  gaps would corrupt windows and lag baselines.
- **Leakage and reproducibility safeguards:** Fixtures contain explicit
  timestamps and no random data, so results are deterministic.
