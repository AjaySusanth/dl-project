## 3. What I implemented

Created the architecture-defined directories and minimal placeholder files so
empty directories remain visible. Python package markers were added to the
`src` packages because these directories will contain importable modules.

### File-by-file explanation

#### `.gitignore`

- **Responsibility:** Prevent generated or local-only files from being tracked.
- **Changes:** Added rules for raw and processed data, artifacts, Python
  bytecode, test caches, virtual environments, coverage output, and Streamlit
  local state.
- **How it works:** Git ignores matching paths and file patterns anywhere
  below the repository root.
- **Why this design:** Data and model outputs can be large and reproducibility
  depends on regenerating them from configuration and source.
- **Connections:** Future ingestion, feature, training, evaluation, and app
  stages will write into the ignored locations.

#### `src/__init__.py` and `src/*/__init__.py`

- **Responsibility:** Mark the planned source areas as Python packages.
- **Changes:** Added empty package markers under `src`, `data`, `features`,
  `models`, `train`, `evaluate`, and `fleet`.
- **How it works:** Python can resolve these directories as package locations
  when later modules are added.
- **Why this design:** It gives the planned modules stable import boundaries
  without implementing any behavior.
- **Connections:** Future scripts will import the source modules from these
  packages.

#### `.gitkeep` placeholders

- **Responsibility:** Preserve currently empty directories in the working tree.
- **Changes:** Added placeholders in `config`, `data/raw`, `data/processed`,
  `scripts`, `app/pages`, `tests`, `artifacts`, and `docs/reports`.
- **How it works:** The files make empty directories observable until real
  configuration, code, tests, outputs, or reports are added.
- **Why this design:** Empty directories alone are not represented by normal
  version-control file inventories.
- **Connections:** Later tasks will replace or supplement these placeholders.

## 5. Key technical decisions

| Decision | Reason | Alternative considered | Trade-off / consequence |
|---|---|---|---|
| Keep raw and processed data under separate `data/` subdirectories | Matches the architecture and protects raw inputs from pipeline writes | Not considered | Requires later stages to use explicit paths |
| Ignore `data/` and `artifacts/` | These are generated or potentially large outputs | Not considered | Generated outputs must be recreated locally |
| Add Python package markers under `src/` | Establishes importable source boundaries | Namespace packages; not considered | Adds minimal empty files before implementation |
| Store the report under `docs/reports/` | Follows the supplied task-report template convention | Root-level report; not considered | Adds a reporting directory not listed in the original architecture tree |
