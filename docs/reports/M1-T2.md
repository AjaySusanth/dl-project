## 2. Pre-coding briefing

### What I planned to do

Implement the raw-trip cleaning rules from the architecture and return a
cleaning report with counts. The function will validate timestamps and pickup

### Why this task is needed

Raw trip files can contain missing fields, invalid durations, records from
unexpected months, or unknown zones. Removing these rows before aggregation
prevents corrupted hourly demand and misleading fleet statistics.

## 3. What I implemented

Added `clean_trips`, which copies the required raw columns, coerces timestamps,
and applies the cleaning rules in sequence:

1. Missing pickup/dropoff timestamps or pickup zone.
2. Pickup month outside the configured month list.
3. Duration below the minimum, above the maximum, or not finite.
4. Pickup zone absent from the lookup table.

It returns a reset-index DataFrame and a report containing counts for each
rule, input rows, and output rows.

### File-by-file explanation

#### `src/data/ingest.py`

- **Responsibility:** Load and clean raw trip records.
- **Changes:** Added `clean_trips` and the lookup filename constant.
- **How it works:** The function validates configuration and required columns,
  loads or accepts the lookup table, applies masks sequentially, logs nonzero
  removal counts, and returns cleaned rows plus a report.
- **Why this design:** Sequential masks make each report count describe the
  rows removed at that stage rather than overlapping categories.
- **Connections:** M1-T3 will aggregate the cleaned DataFrame into a complete
  hourly zone table.

## 4. Architecture and data flow

`raw trip DataFrame + config + zone lookup → clean_trips → cleaned trip DataFrame + report`

The cleaned rows still contain trip-level timestamps and pickup zones. No
hourly table is written yet.

## 5. Key technical decisions

| Decision | Reason | Alternative considered | Trade-off / consequence |
|---|---|---|---|
| Apply masks sequentially | Makes rule counts non-overlapping and explainable | Calculate all masks on original rows; not considered | A row is reported under its first applicable rule |
| Accept an optional lookup DataFrame | Supports deterministic tests without repeated file I/O | Always read the CSV; not considered | Callers must provide a lookup with `LocationID` when overriding |
| Coerce invalid timestamps to missing | Makes malformed timestamp values follow the documented missing-field rule | Allow parsing exceptions to escape; not considered | Malformed values are counted as missing fields |
| Preserve only architecture-defined columns | Keeps the cleaning contract narrow | Carry all raw columns forward; not considered | Later stages cannot use unapproved raw fields without a specification change |

## 6. Deep learning / data-science explanation

- **Concepts used:** Data validation, filtering, and feature-target integrity.
- **Inputs and targets:** Each input row is one trip. This task validates the
  timestamps and pickup zone before trips become hourly pickup targets.
- **Math or loss function:** Duration is calculated as
  `dropoff - pickup` in minutes; no model loss is involved.
- **Training/evaluation implications:** Invalid or out-of-period trips could
  inflate or distort demand counts and therefore model training and metrics.
- **Leakage and reproducibility safeguards:** Only configured pickup months are
  retained. The lookup determines valid spatial categories consistently.
