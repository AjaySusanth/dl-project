## 3. What I implemented

Added a thin CLI with a default configuration path of
`config/default.yaml`. It loads the selected configuration, calls
`load_trips`, `clean_trips`, and `aggregate_hourly`, creates the processed
directory, writes the Parquet result, and logs the JSON cleaning report and
output row count.

### File-by-file explanation

#### `scripts/ingest.py`

- **Responsibility:** Orchestrate the ingestion stage from the command line.
- **Changes:** Added argument parsing, logging, stage calls, output writing,
  and explicit handled failure statuses.
- **How it works:** `main()` returns `0` on success and `1` for expected
  configuration, input, filesystem, or validation errors. The module exits
  through `SystemExit` when run as a script.
- **Why this design:** Pipeline side effects belong in the script while the
  transformations remain reusable and testable in `src/data/ingest.py`.
- **Connections:** Calls the M1-T1, M1-T2, and M1-T3 functions.

## 4. Architecture and data flow

`config → load_trips → clean_trips → aggregate_hourly → data/processed/hourly_all.parquet`

The output is the complete hourly table consumed by M2 zone selection.

## 5. Key technical decisions

| Decision | Reason | Alternative considered | Trade-off / consequence |
|---|---|---|---|
| Keep orchestration in the script | Matches the thin-wrapper architecture | Put file I/O in transformation functions; rejected | The functions remain reusable and easier to test |
| Log the report as JSON | Makes counts machine-readable while remaining visible in the CLI | Print a Python dict; not considered | Log formatting is controlled by the logging configuration |
| Return a nonzero status for expected failures | Supports automation and clear failure detection | Allow traceback-only failure; rejected | Unexpected programming errors still surface normally |

## 6. Deep learning / data-science explanation

- **Concepts used:** Pipeline orchestration and artifact production.
- **Inputs and targets:** Raw trip records become cleaned rows and then hourly
  pickup-count targets; no model tensors are created yet.
- **Math or loss function:** No model loss is involved.
- **Training/evaluation implications:** A complete, persisted hourly table is
  required before chronological windows and baselines can be built.
- **Leakage and reproducibility safeguards:** The exact configuration path
  controls the input months and output paths; no random operation is used.
