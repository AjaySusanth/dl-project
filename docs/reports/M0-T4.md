## 3. What I implemented

Added a small configuration module with three responsibilities:

1. Read and validate YAML mappings.
2. Recursively merge a configuration override into the default mapping.
3. Seed Python, NumPy, and PyTorch.

### File-by-file explanation

#### `src/config.py`

- **Responsibility:** Provide configuration loading and reproducible seeding.
- **Changes:** Added `_read_yaml`, `_merge_config`, `load_config`, and
  `set_seed`.
- **How it works:** `load_config` reads the requested YAML. For a non-default
  file such as `smoke.yaml`, it reads the sibling `default.yaml` first and
  recursively replaces only supplied nested values. `set_seed` seeds Python
  and NumPy immediately, then imports PyTorch and seeds its CPU and available
  CUDA generators.
- **Why this design:** Recursive merging preserves all full-run defaults while
  allowing focused smoke overrides. The PyTorch import is delayed until
  `set_seed`, so configuration reading has a smaller dependency surface.
- **Connections:** Future scripts will call `load_config`; training and other
  randomized stages will call `set_seed`.

## 4. Architecture and data flow

The configuration path is now:

`config/default.yaml or config/smoke.yaml → load_config → stage configuration`

For smoke mode:

`default.yaml + smoke.yaml → recursively merged dictionary → pipeline stage`

No raw data was read and no processed artifact was created.

## 5. Key technical decisions

| Decision | Reason | Alternative considered | Trade-off / consequence |
|---|---|---|---|
| Recursively merge nested mappings | Smoke files contain only intentional overrides | Shallow update; not considered | Nested defaults are preserved correctly |
| Treat `default.yaml` as the base for non-default files | Matches the default/smoke configuration design | Require callers to merge manually; not considered | Non-default files must live beside the default |
| Import PyTorch inside `set_seed` | Configuration loading can work independently of the deep-learning runtime | Import at module load; not considered | A missing PyTorch installation is reported when seeding is requested |
| Raise explicit errors for missing files and invalid roots | Prevents silent fallback to incorrect settings | Return empty configuration; not considered | Callers receive a clear failure instead of a success-shaped result |

## 6. Deep learning / data-science explanation

- **Concepts used:** Configuration inheritance and random seeding.
- **Inputs and targets:** Configuration values define future input paths,
  features, model settings, and target horizons; this module processes no
  observations.
- **Math or loss function:** Not applicable.
- **Training/evaluation implications:** Identical seeds make repeated runs
  comparable, although exact reproducibility can still depend on hardware and
  framework behavior.
- **Leakage and reproducibility safeguards:** The loader does not alter the
  documented chronological split or train-only rules. It makes shared
  settings available consistently, and `set_seed` covers Python, NumPy, and
  PyTorch sources of randomness.
